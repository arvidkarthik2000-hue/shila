The 2026 engine landscape

General engines run thousands of models; model-specific engines run one or two, usually 1.5–3× faster on one hardware class, with their own weight formats. Almost every 2026 specialist was built with an AI coding agent around Qwen3.8-27B or Qwen3.8-Flash-Next.

Ask your AI assistant what your machine can run

SHILA ships an MCP server. Add it to Claude Desktop, Claude Code, Cursor or any MCP client and ask in plain words: “can I run LFM2.5-24B-A2B on this laptop?”, “what is the cheapest box for Qwen3.8-27B at 30 tok/s?”. It can inspect the computer it runs on, reads any Hugging Face model, and answers with the quant, the speed estimate and the engine commands. Needs Node.js 18 or newer; nothing else to install.

Tools it exposes

  • check_compatibility: model + machine → verdict, best quant file, estimated tok/s, memory, ranked engines with commands, published measurements
  • what_can_i_run: machine → every catalogue model ranked by speed
  • cheapest_hardware: model + minimum tok/s (+ budget in ₹) → boxes, cheapest first
  • probe_this_machine: detects RAM, bandwidth, CPU, GPU and VRAM of the computer the server runs on (read-only)
  • list_models, list_hardware, list_engines

How the numbers are computed
Memory. weights (the real file size of that quant) + KV cache (2 × attention layers × KV heads × head dim × 2 bytes × context × users, from each model’s config) + a runtime allowance (0.8 GB + 0.6 GB per 32K of context). Discrete GPUs keep 0.6 GB free; Windows reserves 4 GB of RAM, Linux 3. Macs can wire ~70–78% of unified memory to the GPU by default, or RAM − 3.5 GB with the sysctl raised. Strix Halo / Spark keep 12–16 GB for the OS.
Placement. In order: all in VRAM → unified memory → MoE experts in RAM with the rest on the GPU (llama.cpp --n-cpu-moe) → dense layers split → CPU / iGPU over RAM → experts streamed from SSD. Flash-Next’s 28.8 GB n-gram table is counted as SSD-resident when the toggle is on (llama.cpp --tensor-read-lazy auto).
Decode speed. Each token reads the active weights (active params × bytes per param of that file) plus the KV cache in play; ms = bytes ÷ (bandwidth × efficiency) + layers × per-layer overhead + attention compute. Efficiencies: CUDA 0.88, Metal 0.88, Strix/Spark 0.88, iGPU Vulkan 0.65, desktop CPU 0.45 (MoE) / 0.60 (dense), N-series CPU 0.45, Pi-class 0.55–0.70; RAM-resident experts 0.50. Architecture multipliers: LFM conv blocks ×1.15, Qwen GDN ×0.95, Flash-Next ×0.70. Calibrated against the cited measurements; expect ±30%. Drafting (MTP / DFlash / DSpark) is not included in the estimate; it adds 1.5–2.5× on dense models and 1.1–1.3× on MoEs.
Prompt speed. effective TFLOPS of the compute unit ÷ (2 × active params), halved when the n-gram table streams from disk and reduced to 60% when experts live in RAM.
What is not modelled. Expert caches (llama.cpp --moe-cache-mib, Strata, Infernix) that keep hot experts in VRAM, thermal limits on small boxes, PCIe generation, and concurrency throughput. Users only change the memory budget.
